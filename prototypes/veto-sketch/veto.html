Can a Script refuse what the Host is about to do?

A board game asks its Scripts "may this piece make this move?", and a sign-up form asks "may this form be submitted?". A Script answers by running a , deciding Handler that may veto. This page lets you push that model through the awkward cases: the Script is busy, the answer takes several Pumps, the Handler crashes, the Host gives up, a parent object also has a say, and several Scripts decide at once.

The rule being tested: the verdict is sealed when the Run handling the decision reaches its first Suspension Point, or ends without passing the message on. A veto seals it as vetoed. Reaching a wait or the end seals it as allowed. A crash, a Limit Fault, a cancel or a stop before the seal leaves it undecided, and the Host picks what that means. The Host only ever learns the verdict from a Pump's reports.
