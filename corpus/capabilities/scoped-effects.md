# Scope and Segment-effect coverage

This reconciles every row of [chapter 11's matrix](../../spec/11-the-trace-and-conformance.md#scope-and-segment-effect-conformance-scenarios). The TS completion gate is [scoped-conformance.test.ts](../../impl/ts/tests/scoped-conformance.test.ts): every `scope-*` and `effect-*` case runs normally, with automatic save/restore, and with Stub inputs removed so the recorded calls, acknowledgements and hook outcomes supply Host results. Existing cases continue through `bun run corpus:run`.

The expected Traces were generated by the TS Core and checked for lifecycle order, outcomes, disablement, rollback bindings and Segment ids. Their first **human review is pending** in #222. They are parity requirements for the Go Core; the Go Core has not executed them. Passing this gate establishes TS Core coverage, not Message Layer transport conformance.

In the table, **Scopes** means [scopes.test.ts](../../impl/ts/tests/scopes.test.ts), **Effects** means [segment-effects.test.ts](../../impl/ts/tests/segment-effects.test.ts), **Integration** means [scoped-integration.test.ts](../../impl/ts/tests/scoped-integration.test.ts), and **Replay** means [scoped-replay.test.ts](../../impl/ts/tests/scoped-replay.test.ts). Host-only pointers name executable tests, rather than documentation as evidence.

The [Session consumer test](../../impl/ts/tests/session.test.ts) feeds typed lifecycle failures and effect-failed outcomes to rendering and checks that neither produces a success value or a crash. It also verifies that fatal Reload/replacement reports preserve the previous Session Source and Library definitions. Ordinary Session Transcripts remain part of the existing corpus and [transcript tests](../../impl/ts/tests/transcript.test.ts); the REPL delegates execution and rendering to that Session Host. Session mock declarations do not expose scope or Segment-effect metadata, so no new Session Command or transport is introduced.
