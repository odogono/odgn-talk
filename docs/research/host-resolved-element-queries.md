# Host-resolved element queries, after Apple Events

Research for the part [ADR 0100](../adr/0100-object-element-references-use-a-fixed-spelling-and-a-host-collection.md) deferred: `every element … whose`, range selection and enumeration over an Object Collection. Checked 2026-10-26 against revision `4263024b`. The question is whether the Apple Events object specifier model, which resolves a whole path in the target application, is a good design for resolving an element query in one Host Crossing rather than one per lookup. This is evidence for a decision, not an ADR. The element forms below are hypothetical syntax that no Core parses, so they are fenced as `text`.

The sources are William R. Cook's [AppleScript paper](https://www.cs.utexas.edu/~wcook/Drafts/2006/ashopl.pdf) (HOPL III draft, 2006; cited by section) and chapter 6 of Apple's *Inside Macintosh: Interapplication Communication*, "Resolving and Creating Object Specifier Records" (1996 edition in Apple's legacy archive, marked obsolete). Every Apple claim below was read on the linked page.

## Recommendation

**Specify Option A, Core-side resolution, as the meaning of every element query, and keep Option B, Host-declared bulk resolution, as a later opt-in that must give the same answer.** Apple's own design had the same split: its library resolved paths and tests generically through per-object callbacks, and an application could opt in to resolving whose tests itself and decline any one of them. The split carries over well. The reason for Apple's design, a 1/60 s process switch per message, does not apply in-process, and it applies only weakly behind the Message Layer at Folio's scale. The bulk path also brings a problem Apple never had to solve: Apple let each application interpret comparisons itself, while NorthTalk needs the Host's answer to equal the Core's, with NFC text and decimal numbers. Nothing measured yet says Option B is needed. Build A, measure a real query behind the Message Layer, and decide B on those figures.

## What Apple Events did, and why

- **Latency drove it.** In 1990 the Macintosh OS switched processes no more than 60 times a second, so a script making one remote message per method call "would take several seconds" for work that took a fraction of a second in-process (Cook §2.3). Apple Events instead pack a verb and object specifiers into one message, "in effect a small query/update program" that the target interprets (§2.3). Cook calls this a "large-granularity messaging model" (§9), and also "certainly inferior to RPC mechanisms for single-machine or in-process interactions" (§10).
- **Specifiers are queries.** An element is multi-valued and a property single-valued, and conditions select elements by their properties, which made specifiers "a form of query language" (§2.3.1). AppleScript's reference grammar has ordinals, `every`, ranges (`windows from 1 to 10`) and `whose` (§3.2, Fig. 3). Specifiers travel as nested descriptor records with class, property, index and container fields; events may carry a transaction ID that the target must perform atomically or reject (§2.3.2).
- **A generic resolver with application callbacks.** "The Apple Events team created a support library", which "interprets nesting and conditions in the object specifiers, while using application callbacks to perform primitive property and element operations" (§2.3.1). Apple's documentation confirms the split. [`AEResolve`](https://developer.apple.com/library/archive/documentation/mac/IAC/IAC-232.html) parses the specifier, starts at the outermost container and calls the application's object accessor for each class and container, which returns an opaque token. To handle tests the application also supplies an object-counting function and an object-comparison function. The counter tells the resolver "how many elements it must test", and the comparer "compares one element to another element or to a descriptor record and returns `TRUE` or `FALSE`".
- **Restricted test forms.** [`formTest`](https://developer.apple.com/library/archive/documentation/mac/IAC/IAC-238.html) key data is only a comparison descriptor or a logical descriptor. A comparison holds one of eight operators (greater than, at least, equals, less than, at most, begins with, ends with, contains) between the element being examined, or an object specifier from it, and another object or plain data. A logical descriptor applies AND, OR or NOT to a list of such terms, with short-circuit evaluation. Other key forms are `formAbsolutePosition` (a signed offset from either end, or first, middle, last, any or all) and `formRange` (two boundary specifiers, inclusive when they are the same class) ([key forms](https://developer.apple.com/library/archive/documentation/mac/IAC/IAC-237.html)).
- **The application interprets the comparisons.** "It is up to your application to interpret the comparison operators it receives", and a comparer that cannot compare returns `errAEEventNotHandled` ([comparison function](https://developer.apple.com/library/archive/documentation/mac/IAC/IAC-249.html)). Comparison semantics were never the resolver's own.
- **The opt-in.** The resolver collapses a test and a position or range into one internal `formWhose` record. An application that sets [`kAEIDoWhose`](https://developer.apple.com/library/archive/documentation/mac/IAC/IAC-246.html) in `AEResolve`'s flags receives that record, holding the index or range together with the test, and may translate it into its own query language. Apple says this "is useful only for applications that can make use of a test combined with either an absolute position or a range". An accessor that declines returns `errAEEventNotHandled`, and the resolver retries "just as if the `kAEIDoWhose` flag were not set". `kAEIDoMarking` separately lets an application [mark matches](https://developer.apple.com/library/archive/documentation/mac/IAC/IAC-250.html) instead of building a token list, which helps when the tokens "might not all fit in memory" ([flag values](https://developer.apple.com/library/archive/documentation/mac/IAC/IAC-267.html)).
- **What it cost.** "Supporting Apple Events was frequently quite difficult" (§2.3.1), and "writing scriptable applications is difficult" (§9). User tests found that "casual users don't easily understand the idea of references" (§9). Automatic dereferencing hid the line between a reference and its value, which Cook names as one of the language's hardest design problems (§3.2).

## What NorthTalk resolves today

The [object element contract](../../spec/embedding/object-elements.md) selects one member or counts members. Ranges, enumeration, `every element` and element Whose heads are outside it. `every element of p whose …` is a syntax error at `element`, and `the first element of p whose …` is one at `whose`.

- **Three getters, one crossing each.** An Object Kind declares `Count`, `At` (a signed position, so the last member costs one callback) and `Find` (exact NFC name), each with a declared cost. A lookup makes at most one callback and never materializes the collection. Missing selections give Nothing.
- **Charging.** `get-element` costs `3 + scalars(selector) / 8` Fuel, and `count-elements` costs 3 ([chapter 8](../../spec/08-the-abstract-machine-and-the-cost-model.md)). The callback's declared cost is paid before the call, and nothing is called if payment fails. The returned Value's conversion is charged as for a property getter. Folio declares 1 Fuel and no allocation per callback ([Folio's policy](../../tooling/creative/README.md#element-references)).
- **The Trace.** Each callback is one `prop` record with `name` `elements`, an `op` of `count`, `at` or `find`, and a Value-typed `selector` ([chapter 11](../../spec/11-the-trace-and-conformance.md#the-trace)). Replay answers from the record and redoes conversion and charges. Over the Message Layer, each callback is one interim `prop` need ([chapter 9](../../spec/09-embedding.md#messages)).
- **Authority and stability.** Holding the receiver authorizes its collection reads, with no Grant. Membership must stay stable throughout one reference, because the Host serializes collection edits with the Group worker. Callbacks are synchronous, read-only and non-reentrant, and they cannot `Charge`.
- **Whose Clauses on values.** [ADR 0074](../adr/0074-a-whose-clause-picks-the-chunks-whose-condition-holds.md) walks a snapshot of the plural property, binds `it` to each chunk, and limits the condition to Built-ins, with Host Object property reads allowed as anywhere in a Run.

## Option A: the Core resolves

```text
put every element of thisPage whose fill is "red" into reds
put the first element of thisPage whose name begins with "cell_3" into c
put elements 2..5 of thisPage into some
```

Lower these onto the existing getters. `every` does one `Count`, then `At` for each position. Each iteration binds `it` and runs the condition, so a Whose Key such as `fill` is one property `get`. An ordinal stops at its match, as in ADR 0074. A range calls `At` once for each position it covers, and calls `Count` only when it has to resolve ends with mixed signs.

- **Crossings:** `2n + 1` for `every … whose` with one property key over `n` members. Tests on `id` or `objectKind` read Core-held data and cost no crossing.
- **Fuel:** in Folio, at least 4 Fuel per `At` (the 3 base and Folio's 1) and 3 plus the getter's declared cost per property read, plus result conversions and the loop's own instructions.
- **Determinism and replay** need nothing new: each callback is an existing `prop` record. Comparison is the Core's, so ADR 0011's NFC text and ADR 0002's decimal equality hold without Host help.
- **What changes:** ADR 0074's snapshot becomes the contract's stability rule, extended across the whole walk. That is sound because the condition can call no Operation and getters are read-only. The walk never materializes the collection, which keeps ADR 0100's reason for rejecting "return all Elements through a property".

## Option B: the Host resolves, by declaration

The Object Kind's `elements` declaration adds an optional `select` callback with its own costs. Like `kAEIDoWhose`, it receives a whole query: a range or ordinal and a restricted test. It answers with a list of member handles, or with a declined answer that sends the Core back to Option A.

- **Which conditions could ship.** ADR 0074's condition is already restricted to Built-ins, so the Core can classify it at load. A shippable test would be like Apple's comparison and logical descriptors: a declared property of `it`, compared with a value that does not depend on `it`, joined by `and`, `or` and `not`. The Core evaluates the right-hand values once, before the crossing. Anything else, such as arithmetic on `it`'s properties, a nested chunk or `the length of it`, stays Option A. A conservative first set is `is` and `is not` on Nothing, booleans, text and integers. Ordering, `contains` and Quantities can wait until the semantic risk below is settled.
- **Fuel.** A declared cost per call can't cover a scan whose size depends on the collection, and a getter can't `Charge`. Billing after the work is the approach [ADR 0082](../adr/0082-metered-operations-authorize-work-through-the-pump.md) rejected. One shape that fits the existing rules is a `Count` crossing, then a Core charge of the declared per-member cost times the count, paid before the `select` crossing, then result conversion as usual. That makes two crossings, not `2n + 1`. Making `select` a Metered Operation instead would bring in Calls, which collection callbacks deliberately lack.
- **The Trace.** One `prop` record with `name` `elements`, a new `op` such as `select`, the query encoded as a map in the existing Value-typed `selector` field, and the handle list as `value`. A declined answer is recorded too, followed by Option A's records. Replay answers from the records, so it stays exact whichever path ran. Because cross-Core comparisons already require the same declarations, both Cores make the same choice between A and B.
- **Consistency risk.** Apple let each application decide what `equals` meant. NorthTalk can't. Text crosses into the Core as NFC, but a Host's native strings need not be, and NorthTalk text comparison is exact and case-sensitive on NFC ([ADR 0011](../adr/0011-text-is-nfc-grapheme-clusters-compared-exactly.md)). Numbers are 34-digit decimals with `1.0 = 1` ([ADR 0002](../adr/0002-single-decimal-number-type.md)), not floats. A property the member's kind lacks reads as Nothing ([chapter 4](../../spec/04-expressions-and-statements.md)). A heterogeneous collection such as Folio's seven Element kinds hits that rule on every query. The Core can check Shape, Group and liveness of the returned handles, but it cannot check completeness without the `n` property reads that B exists to avoid. This trust already exists in a smaller form, since the Host must keep `Count`, `At` and `Find` consistent, but B widens it from membership to semantics.
- **Authority.** ADR 0100's rule carries over: holding the receiver authorizes reading its members, and each member's properties are readable by whoever holds the member. A test may name only properties that the member kinds declare, so B reveals nothing that A could not. A test on an undeclared name must behave as Nothing, as A's would.
- **Errors.** In A, a getter failing on member `k` raises at `k`, after `k − 1` evaluations. B must either report that same failure or decline, or else the two paths raise different errors.

## What a crossing costs

| Figure | Value | Source |
| --- | --- | --- |
| Capability call p50, Zig reactor, C Host on wasmtime | 7.5 µs | [Zig measurements](zig-message-layer-measurements.md#c-host-on-wasmtime) |
| Capability call p50, Zig reactor, Elixir Host on Wasmex | 55.3 µs | [Zig measurements](zig-message-layer-measurements.md#elixir-host-on-wasmex) |
| Capability call p50, Elixir Host on the native Go sidecar (historical, retired Go Core) | 25.0 µs | [Message Layer measurements](message-layer-measurements.md#results) |
| Bare export call: Bun, Wasmex | 0.01 µs, 17–29 µs | [Message Layer spike](message-layer.md) |

None of these times a `prop` need. The measurements say so: "Suspending Operations, `prop` needs, restore and the Message Layer's unsupported messages aren't timed" ([fog](message-layer-measurements.md#fog)). The Capability call figure is the closest stand-in, since an interim `prop` need has the same shape as an `op` need, but that is an assumption. No note measures an in-process property getter on either Core.

On that assumption, `every element of p whose fill is "red"` over Tetris's 216 rectangles makes 433 crossings under A. That is about 3.2 ms on the C Host and about 24 ms on Wasmex, against one or two crossings under B. The Wasmex figure exceeds a 16.7 ms frame at 60 Hz. The C figure fits, but not as a per-frame habit. In-process, the export call itself is 0.01 µs, so A's cost is the Core's own per-element work, which B does not remove.

## When it isn't worth it

- **In-process Hosts.** Folio runs the TS Core in the page, with no Message Layer between Script and Host, as can any Bun or Node Host that embeds the TS Core. Cook's own judgment is that the model loses to direct calls in-process (§10).
- **Folio's scale.** Tetris has 200 board cells and a 16-cell preview ([Folio guide](../../tooling/creative/README.md#tetris)), the 216 rectangles ADR 0100 mentions. It paints by computed name, with one `Find` per changed cell, not by query. ADR 0100 already points the board-painting cost at a separately measured Grid Element.
- **Small collections.** The Count crossing B needs for charging is a fixed cost, so B only wins once `2n + 1` clearly exceeds 2.
- **The Host author's burden.** B asks each Host to reimplement NorthTalk comparison, Nothing for missing properties, and error order. That is the burden Cook says made scriptable applications hard to write (§2.3.1, §9), made harder by an exact-parity requirement that Apple never had.

## Open questions for the ADR

1. Must B's answer equal A's on the same Host state, as a Host obligation like `Count`/`At`/`Find` consistency? Or is B allowed its own semantics, which would make the language's meaning depend on the Host?
2. How should the Conformance Corpus check B? The corpus runner could implement `select` by evaluating A over its fixture list, but that tests the Core's encoding, not a Host's comparison.
3. Which comparison forms ship in the first version? Is `is` on text, booleans, integers and Nothing enough, or are ordering and `begins with` needed?
4. Is the charge a `Count` crossing plus declared cost per member, or a declared bound with a refusal, or something metered?
5. Does `the last element … whose` walk forward, as ADR 0074 requires for values, or backward through negative `At`? Backward is cheaper, but the condition then runs on different members, which is visible when it fails.
6. Do range selectors for elements reuse `..` ranges, which are a Value kind and currently a `wrong kind` selector, or a spelling closer to AppleScript's `from … to`?
7. Should a decline be per query, like `errAEEventNotHandled`, or only declared per Object Kind?
8. Before any of this, which Host actually needs B? Name the Message Layer Host and collection size, and time a `prop` need there.
