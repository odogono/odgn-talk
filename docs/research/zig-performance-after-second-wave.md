# Zig performance priorities after the second optimization wave

At revision `0aed90d3`, native Zig is 1.51× faster than AppleScript overall across the 21 common workloads, but still loses nine rows. The largest remaining ratios are loop 5.05×, Quantity 2.43×, addition 1.90×, division 1.68× and multiplication 1.60×. List update is 1.36×, Fibonacci 1.24×, lambdas 1.18× and Text build 1.15×. These use the latest [four-way report](../../bench/results/2026-10-15-four-way-after-ts-zig-summary.md) and [full-precision data](../../bench/results/2026-10-15-darwin-arm64-apple-m5-zig-ts-applescript-gopher-lua-after-ts-zig-0aed90d3.json). Run times exclude Load. The three-repeat comparison identifies workload priorities; it does not estimate an optimization's speedup.

The five recommendations below are investigation scopes, not implementation promises. The [fresh native profiles](../../bench/results/2026-10-15-zig-next-priorities-profiles.json) sample this same revision twice for two seconds at 1 ms intervals. The report labels `before` and `after` are capture A and capture B of the **same binary**, not an optimization experiment. Percentages count only Pump-subtree samples, are inclusive and overlap; compiler inlining limits named attribution. A paired prototype must establish actual speedup.

## 1. Instruction scratch and execution-boundary overhead

Target `core/loop`, arithmetic and calls. [`Group.execute`](../../impl/zig/src/machine/machine.zig) still resets the scratch arena at every instruction, then checks landing, preemption and operand protection, builds/releases charging measures, applies limits and dispatches the outcome. Arithmetic instructions often need no scratch allocation. Investigate a cheap scratch-used/dirty path or an equivalent allocator-level reset fast path before considering broader dispatch restructuring. Keep instruction boundaries intact; this is not permission to batch Fuel charges or postpone cancellation/preemption checks.

Fresh captures attribute 124/1,534 and 101/1,523 unsliced loop Pump samples (8.1%/6.6%) to scratch reset, with charging at 11.7%/11.6%. Addition scratch reset is 7.3%/7.9%. These establish a material residual seam rather than a promised removable share. The [earlier bookkeeping profiles](../../bench/results/2026-10-14-zig-instruction-bookkeeping.md) attributed about 4% of loop Pump samples to scratch reset, and the [later cost-specialization profile](../../bench/results/2026-10-14-zig-cost-evaluation.md) leaves charging at 11.2% in its loop capture. These are historical evidence for where to investigate, not current shares. The two per-instruction `Operands` copies and generic static charge-formula interpretation have already been removed; do not repeat those tasks.

Validate sliced and unsliced loops, protected operands, Host crossings, allocation refusal, errors and cleanup. The AppleScript loop uses a native counted loop, whereas [the NorthTalk workload](../../bench/scripts/core/loop.talk) explicitly compares and increments; the 5.05× gap cannot all be assigned to dispatch.

## 2. Repeated Text growth and its repeated scans

Target `text/build`, then larger ASCII and Unicode growth probes. [`concatText`](../../impl/zig/src/value.zig) already transfers its joined ASCII buffer directly into the result; the old extra normalization copy has been removed. It still validates both inputs, copies the entire growing prefix and scans the join for ASCII, while charging can count Characters again. Investigate trusted internal NFC/UTF-8 inputs, reusable immutable Character/ASCII metadata, or a persistent Text/builder representation only if profiles and size sweeps show the copying dominates.

Fresh Text-build captures put charging at 413/1,527 and 393/1,523 Pump samples (27.0%/25.8%). The first raw call tree also names `concatText` and UTF-8 validation prominently; these overlap because validation is called inside concatenation. Internal immutable Text operands have already passed UTF-8/NFC validation, so distinguish trusted Core-to-Core concatenation from public Host input validation. Preserve invalid-UTF-8 refusal at the latter boundary. This current evidence makes Text a higher-priority narrow investigation than the small absolute peer gap alone suggests.

Keep the scope distinct from already optimized [Character indexing](../../bench/results/2026-10-14-zig-character-indexing.md). Text build's present 1.15× AppleScript gap is smaller than the numeric gaps, so start with a narrow metadata/scan prototype before a rope. A representation change must preserve NFC across joins (including combining marks and Hangul), CRLF graphemes, exact scanned/Character charges, retained old Texts, Host contiguous output and physical allocation accounting. Counting Characters cannot simply add cached counts across arbitrary joins.

## 3. Scalar ownership and iterator/call traffic

Target Fibonacci, lambdas, calls and integer loops. [`Value.retain`/`release`](../../impl/zig/src/value.zig), machine stack/local movement and `costs.Measures` still manage heap-node references for small immutable Number/Boolean/Nothing Values. [`Group.instruction`'s range `next`](../../impl/zig/src/machine/machine.zig) also converts both fixed endpoints to integers on every iteration before constructing the next Number. A derived integer endpoint cache, consistent with saved position and owned subject, is a small initial prototype; scalar release specialization or fewer temporary owned references at a proven seam are subsequent candidates.

Fresh captures attribute 8.6–9.2% of loop Pump samples and 10.1–10.2% of addition samples to allocator work; release is 4.5–5.3% and 4.3–5.2%, respectively. These overlap other categories and include cached allocator paths; they do not mean parent allocation requests remain high. There are no fresh Fibonacci/lambda profiles here, so extrapolation to those rows is a hypothesis.

The [scalar-constructor report](../../bench/results/2026-10-14-zig-scalar-constructors.md) already removes poison fills and large union copies for Number/Boolean. The [call-storage report](../../bench/results/2026-10-14-zig-call-storage.md) already implements bounded frame/local buffer reuse. Increasing those caches or repeating narrow construction is unlikely to address the remaining work. A previous boxed-Quantity layout added payload allocations and was rejected; a broad representation rewrite needs new evidence and its own tradeoff analysis.

Any borrowing or specialized release must preserve observable canonical locals, retained-state sizes, Host ownership, allocator refusal and snapshots. Reducing reference traffic is distinct from deleting live canonical temps. Do not infer that a value is dead merely from source-level last use.

## 4. Numeric hot-path measurements and exact kernels

Target all four numeric rows, particularly Quantity. [`costs.digits`](../../impl/zig/src/machine/costs.zig) counts coefficient digits with repeated `u128` division by ten whenever a formula requests digits. A table/bit-width estimate with exact power-of-ten correction is a bounded candidate. Check the generated code first: compiler lowering and operand distributions determine whether it is material. Preserve exact 1–34 digit counts, including zero and boundaries; use the existing interpreter as the independent charge oracle.

Profile [`Decimal.calculateExact`](../../impl/zig/src/decimal/decimal.zig) separately from this measure work. Its arithmetic uses checked `u128` operations, and terminating division currently emits fractional digits with repeated division/remainder. Wider fixed-width or divisor-specific exact kernels could help only if the current profiles justify them. Keep the existing general path as an independent fallback/oracle; do not substitute binary floating point or remove cohort/exponent, half-even, overflow or subnormal behavior.

Fresh Quantity captures attribute 113/1,529 and 105/1,524 Pump samples to Decimal work (7.4%/6.9%), with charging at 7.7%/9.5%. Addition Decimal attribution is 6.5%/7.2%. Most time therefore remains outside the named Decimal kernel, and the earlier much larger Decimal percentages are stale. Inlining limits these measurements, so use isolated kernels plus whole Runs when deciding priorities.

For Quantity, [`Value.arithmetic`](../../impl/zig/src/value.zig) still converts operands to Base Units, performs arithmetic and converts to the resulting Unit in the specified order. Narrow borrowing/copy reduction and faster individual exact operations are safer investigation targets than algebraically merging factors. [Static Unit descriptors, active masks, ordered plans and factor-one skips already landed](../../bench/results/2026-10-14-zig-unit-metadata.md). [Exact terminating division and integer `div`/`mod`](../../bench/results/2026-10-14-zig-division-paths.md), [narrow scalar constructors](../../bench/results/2026-10-14-zig-scalar-constructors.md) and [exact comparison shortcuts](../../bench/results/2026-10-15-zig-comparison-paths.md) also already exist. This scope is residual-kernel profiling, not reopening their original work.

## 5. Structurally shared List point updates

Target `collections/list-update`, with a size sweep beyond the suite's eight-item List. [`listSet`](../../impl/zig/src/value.zig) copies and retains the whole visible spine when its input is shared. Machine chunk writes necessarily retain the old root at the present canonical seam. Investigate a chunked/persistent List representation that copies a bounded path while preserving every old version, rather than trying to mutate through those owners. This is a deeper change; use a prototype and reject it if small Lists, sequential iteration, append, memory caps or teardown regress.

Fresh eight-item List-update captures attribute only 67/1,528 and 57/1,530 Pump samples to `listSet` (4.4%/3.7%). Allocator work is 11.3%/12.1% and release 9.4%/8.4%, serving other instructions too. That argues for treating persistent storage as a longer-term size-scaling improvement, not assuming it explains the current whole-workload gap.

The [current ownership investigation](../../bench/results/2026-10-15-zig-local-list-writes.md) establishes why last-use temp retirement was rejected: temps are canonical retained Values, contribute to Persistent State and are serialized. It measured more than 3 MiB of cumulative requested physical bytes for 128 writes to a 3,000-item retained-original List, despite only about 56 KiB Run live-peak growth. Those measurements identify full-spine copying even when few versions remain live. They do not prove a tree is faster for eight items.

Preserve saturated cached logical sizes, sharing/ranks, self-insertion safety, hidden tails, retained versions, allocation refusal, restored frames and allocation-free teardown. Current C Host/List consumers rely on contiguous slices, so account for API/iteration materialization costs rather than hiding them.

## Measurement policy

Profile the current safe-mode native binary separately from timing, count only Pump subtrees, retain raw samples and note inlining. Use alternating before/after pairs against the same base, independently validate output, exact Fuel and logical allocation, and record physical allocations separately. Include size sweeps where asymptotic behavior is the rationale. Keep the four-way runner selection `zig,ts,applescript,gopher-lua`; no WASM/Elixir or other language performance campaign is implied. Peer numeric and loop ports are idiomatic and use different numeric semantics, so their gaps are useful workload targets rather than equivalent-kernel comparisons.
