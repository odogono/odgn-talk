# Domain docs

This repo uses a single-context layout: root `CONTEXT.md` and `docs/adr/`.

Before exploring a relevant part of the codebase, read `CONTEXT.md` and any ADRs that touch that area. If those files do not yet exist, proceed; `/domain-modeling` creates them when terms or decisions are resolved.

Use terms defined in `CONTEXT.md` when naming domain concepts. If an output would contradict an ADR, call out that conflict explicitly.
