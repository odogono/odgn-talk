# Folio browses in place

Folio runs a Project the way HyperCard's browse tool did. The Tools window has two modes, **Browse** and **Edit**. Choosing Browse starts a Play Session on the Page being edited, drawn where the Page was, while the Tools, Script and Errors windows stay open. Choosing Edit, choosing an Element tool or pressing Esc on the desk stops every Script and sound, discards Play State and returns to Edit on the Page the session reached. **Present** in the header runs the same session full-window with the editor hidden; its button becomes **Stop**, which returns to Edit in one step. This supersedes [ADR 0086](0086-creative-play-runs-in-a-worker-and-stop-freezes-the-session.md)'s frozen session and its Restart and Back to Edit controls. Trying a Project no longer means leaving the editor: an author clicks through a Page, sees what broke and fixes it beside the running Page.

Browsing keeps the separation in [ADR 0041](0041-authored-projects-are-separate-from-temporary-play-state.md). HyperCard saved whatever a Script or reader changed while browsing. Folio discards it, so a Script that hides a button or a reader typing into a field never alters authored work, and undo never has to cover Script effects. Scripts stay editable while browsing. An edit changes the authored Project at once and takes effect in the next session; the running session keeps the Scripts it loaded, so a fix never lands half-way through a handler. While presenting, Scripts are read-only, as the editor is hidden.

Script problems go to an Errors window rather than a banner. Each names its owner and line and opens that authored Script; problems are reported against the authored owners, so the links outlast the session and survive renames by falling back to the owner's Page and name. The window opens when the first problem arrives, keeps its list after the session ends, and is cleared when the next session starts, by its Clear button, or when another Project opens. Script name problems that prevent a session from starting appear there too.

The escape path in ADR 0086 stands. Stop still silences audio first and requests sticky Core Stop for every Script before Play State is discarded, so leaving does not depend on a Script's cooperation, and late effects are dropped with the session.

We considered keeping Play as a separate full-window mode with an in-place Stop, which kept one way to run a Project but meant hiding every authoring window to try one button. We also considered reloading a Script into the running session when it is edited, as close to HyperCard's fix-and-click loop as possible; running handlers, Script Variables and pending waits make the result hard to predict, so a fresh session is the boundary.
