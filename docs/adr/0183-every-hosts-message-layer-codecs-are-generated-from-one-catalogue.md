# Every Host's Message Layer codecs are generated from one catalogue

`spec/data/envelope.toml` described only the fields layout of [ADR 0110](0110-request-and-pump-have-an-optional-binary-exchange.md), and its generator emitted name and kind tables. The JSON layout was prose in chapter 9, and the Inspect reply view was in no Data File at all. Go, Elixir, TS and Zig each mapped Load options, Inspect fields and most other messages by hand, with hundreds of string keys per Host. Adding `forbidSuspension` ([ADR 0178](0178-a-host-may-load-a-script-that-must-never-suspend.md)) touched about ten files only to carry one boolean, and Elixir drift showed up only in the weekly Zig workflow. [ADR 0131](0131-the-zig-message-layer-describes-each-need-and-result-once.md) fixed this kind of drift for Needs inside Zig but stopped at the Zig seam. For [#2272](https://github.com/odogono/odgn-talk/issues/2272), the fix extends across every Host.

`envelope.toml` becomes the one catalogue of what crosses the Message Layer. Each message lists the layouts it travels in and how JSON reshapes it. Reply views such as Inspect are a `[[views]]` section. A field the Host fills itself, such as `ref`, `group`, `newGroup` or `refuseWorker`, is marked `host = false`, so a check can name a public option a Host forgot to map. Features are emitted as named constants, not read by array index. Chapter 9's method table is generated from the catalogue.

The generator emits typed records and field descriptors for every Host. Each Host keeps one encoder and decoder per layout that walks those descriptors; Zig walks them at comptime. Both layouts decode to the same typed value, so Zig no longer turns a fields-layout Load into a JSON map. Fully emitted per-message functions were rejected as more generated code for no measured gain; the hot Request and Pump path may switch to them only if a benchmark shows that walking regresses. Each Host's public option names stay hand-written: they follow each language's conventions and its release's semver, and map to a typed field in one line each.

`impl/testdata/envelope-frames.json` gives each vector an optional `json` encoding beside `hex`, both of the same Host-view tree, and `envelope:check` requires every field in each layout it travels in. Every Host runs the vectors on pull requests, Elixir in its own path-filtered job.

The layouts remain independently negotiable ([ADR 0110](0110-request-and-pump-have-an-optional-binary-exchange.md)), and the Exchange lifecycle stays in `exchange.zig` ([ADR 0127](0127-the-zig-message-layer-keeps-an-exchanges-lifecycle-in-one-module.md)). No frame changes. Load and Inspect move first; the remaining messages follow in later issues.

- Amended by #2301:
  - **Vectors:** a vector's `tree` already is the JSON layout of a message that travels in JSON, so no separate `json` encoding is added. `hex` becomes optional instead, and a JSON-only message or reply view has a vector with `tree` alone.
  - **Chapter 9's method table** stays prose. Generating it would move its feature notes into TOML strings. `envelope:check` instead requires each JSON message's row to name every field a Host maps, and to backtick no field the catalogue lacks. Generation is reconsidered once #2306 has catalogued every message.
  - **Scope:** only `load`, `inspect` and the existing fields-layout messages that also travel as JSON are catalogued in JSON.
