# Time has microsecond resolution

An Instant, a Civil Date's time of day and an exact duration are whole microseconds ([#1001](https://github.com/odogono/odgn-talk/issues/1001)). This supersedes [ADR 0015](0015-the-host-drives-the-core-through-a-pump.md)'s nanosecond resolution, which was stated without a reason. Nanoseconds claim more than a Clock reading carries: wall clocks are rarely accurate below a microsecond, and some platforms report only microseconds. Microseconds also match where Values go when they leave a Core. Elixir and Erlang `DateTime`, Postgres timestamps and most SQLite and JSON date conventions stop at microseconds. Under nanoseconds, an Instant a Script builds can't round-trip through those types. Under microseconds, every Instant fits a single 64-bit count of epoch microseconds across the 0001 to 9999 range, which 64-bit epoch nanoseconds can't (1678 to 2262).

The loss moves to the Hosts with nanosecond types. A Go `time.Time` becomes an Instant by truncating toward the past to the microsecond. It never rounds up, so a Clock reading is never later than the time it was taken. The seconds-plus-fraction builders in every Core take microseconds from 0 to 999999 and refuse anything outside that range. Durations still round half-even, now to whole microseconds, when added to a date or waited for. So a wait of half a microsecond or less is a wait of zero.

Text stays strict. `as instant`, `as civil date`, the `$instant` and `$date` tags, Trace values and the `date` Library's parsing accept a fraction of one to six digits. Seven or more raise `can't convert` in a Script and are refused as `invalid value` at the boundary. A native time has a precision its Host can't choose, so it gets a defined conversion. Text was spelled by someone who can spell it at the right precision, so truncating it would quietly break the rule that a value's text reads back as an equal value ([ADR 0003](0003-no-implicit-coercion.md), and the Value Encoding's strict decoding settled by #650). Fractions and differences display at most six digits, with no trailing zeros.

The `nanosecond` Built-in becomes `microsecond`, from 0 to 999999, at the same cost. The `ns` parameter of `makeDateTime` and `atTime` becomes `us`, and `${fraction:n}` takes n from 1 to 6. This breaks Scripts that use the old names and Hosts that pass nanoseconds. The language hasn't reached 1.0, so the change is made at once, with no deprecation window.

Saves stay per Core ([ADR 0008](0008-same-core-save-restore.md)). The save format changes version, and a save written under nanosecond resolution is refused. Hosts start fresh Groups from source and Host-owned data, as for [ADR 0089](0089-the-zig-build-serves-the-message-layer-reactor.md). No converter is supplied.

We considered keeping nanoseconds and truncating only at the Elixir boundary. That leaves a lossy edge at every microsecond store and a Value that can't round-trip through its own Host. We also considered accepting nine-digit text and truncating it, which would spare Hosts that format with Go's `RFC3339Nano`. That puts a silent coercion into the language in return for saving a Host one formatting call. Going back to nanoseconds later would mean the same sweep across the spec, all three Cores and the corpus, so a Host that needs sub-microsecond ordering should carry its own counter alongside the Instant.
