# Snapshot sources may come from the Host

Embedded Hosts already ship their Scripts, so saving those sources again makes mostly idle Groups expensive to store ([#1337](https://github.com/odogono/odgn-talk/issues/1337)). The native TS Core offers an explicit External-source Snapshot alongside its default Embedded-source Snapshot: the Host supplies each Script's base and ordered extensions at Restore, and the Core recomputes their identities and dependencies before accepting any continuation. Missing sources fail; different code requires the Host's explicit variables-only policy and discards the whole Group's continuations. This extends [ADR 0008](0008-same-core-save-restore.md) without frame migration or a silent change of code, and permits variable recovery when an application keeps only its current sources. Retaining historical source inside every save or requiring a separate historical catalogue would preserve the old restore-then-reload path, but would retain the overhead or move that storage requirement onto every Host.

Grant declarations remain in the snapshot and are shared by content: an absent Host binding must still restore as revoked without preventing compilation. Both source modes use compact JSON tuples and dictionaries around the existing graph reconstruction and validation. We chose this over a binary graph codec to reduce repeated structural text while keeping the private payload inspectable and runtime-neutral. The new TS format replaces the old one without a legacy reader; saving remains Core-specific, deterministic and subject to the same accounting and live-effect rules. Other Core implementations and application adoption are separate work.
