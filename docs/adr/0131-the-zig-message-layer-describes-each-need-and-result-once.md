# The Zig Message Layer describes each Need and result once

The Zig Message Layer wrote each op, prop, effect and release Need and read its result separately in JSON and `callbacks-fields-v1`. The copies drifted, so fixes repeatedly had to land twice. For [#1568](https://github.com/odogono/odgn-talk/issues/1568), `need.zig` owns each Need's ordered fields behind one `needFields` writer, the result parsers and one mapping from a layout-neutral callback result to the worker's Answer. As with `reportFields`, the JSON and fields encoders only encode the shared field description.

Each result parser keeps its layout's syntax: JSON's `limit: true` and outcome precedence, or the fields layout's outcome text and optional positional fields. Both feed the same result reader and Answer mapping. Successful Values that cannot resolve get a Host-error reply, as before; malformed failure Data produces a Host-error Answer. The resolver returns `error.WrongGroup` directly, including through nested Values, rather than setting a Group flag for the decoder to inspect. Shared `impl/testdata/envelope-frames.json` vectors and refusal cases exercise both parsers at the module's interface.

This preserves [ADR 0110](0110-request-and-pump-have-an-optional-binary-exchange.md): the layouts remain independently negotiable and can mix within an Exchange. It also preserves [ADR 0127](0127-the-zig-message-layer-keeps-an-exchanges-lifecycle-in-one-module.md): `message.zig` owns frame dispatch, and `exchange.zig` owns the gate and lifecycle. Admission, Trace and restore results remain outside `need.zig`, although the glossary's Need also covers Trace delivery and restore binding resolution. Moving the whole dispatcher would mix those responsibilities; sharing only a struct would leave the duplicated result policy with the callers. No Message Layer frame or public Host interface changes.
