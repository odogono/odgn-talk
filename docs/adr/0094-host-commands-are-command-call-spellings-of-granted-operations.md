# Host Commands are Command Call spellings of granted Operations

An Operation Declaration may be marked `command`, and then any Script whose Grants include that Operation may also call it as a Command Call: `hide welcomeText` calls `folio`'s `hide` as `tell folio to hide welcomeText` would. A Command Call resolves by its Selector to a Handler of the Script, then to an imported one, then to a Host Command, and only if none exists does it climb the Message Path as a `send`. A Host Command is an ordinary Operation call in the caller's Run: it is checked at load against the Grant, charged its declared cost, recorded as a `call`, and its errors are raised at the calling line, so a failure stops the calling Handler. We chose this because Folio wanted HyperCard's `hide`, `show`, `go` and `beep` without an Import, and its workaround, a hidden object with a Script of Handlers at the end of every Message Path, made each call a separate fire-and-forget message: failures didn't reach the caller, errors were reported on line 1 of the caller because the Host only knew the sender, and checkers and language servers needed Host-specific teaching. The `command` flag sits in the Operation Declaration, so the Host Manifest carries it to tooling with no extra teaching.

Resolving in the caller's Run gives up HyperCard's override, in which a Page or Project Script answers `on hide` and `pass hide` before the Host acts. Scripts are actors ([ADR 0004](0004-scripts-are-actors.md)), so a Script further up the path can only take part through a message, and then the call can no longer be checked and fail at the calling line unless every call is written `and wait`. A Host that needs overrides can offer them some other way, such as a Decision the Operation sends first.

This narrows [ADR 0012](0012-capabilities-are-called-through-tell-and-ask.md). The grammar stays the same on every Host, because `hide x` already parses as a Command Call and labels parse the same whatever Handlers exist, and only resolution depends on the Grants, which the loader already checks. What is given up is that `tell` or `ask` marks every effect at its call site: `hide x` reads like a call to a Handler. Suspension stays visible, since a suspending Host Command is written `and wait`. It also narrows [ADR 0020](0020-scripts-share-code-through-stateless-libraries.md)'s resolution order.

## Considered Options

- **Resolve at the end of the Message Path** (#1019 as first proposed): keeps HyperCard's overrides, but the call climbs as a `send`, so a plain `hide x` stays fire-and-forget and errors only reach the caller through `hide x and wait`, which splits the caller's Segment.
- **Resolve in the caller's Run when no Script on the current path has a Handler for the Selector, and climb otherwise:** keeps overrides and checked calls in the common case, but one call site would behave two ways depending on parents the Host can change at any time.
- **Default imports (a Host prelude Library):** simplest, with no Core change, but a Library has no Grants and adds nothing an Operation doesn't already give, and it loses overrides as this decision does.
- **Host-defined syntax** (HyperTalk's XCMDs, rejected by ADR 0012): still rejected. A Host Command adds a resolution step, not syntax.

## Consequences

- **Declaring:** `command` is an optional flag on an Operation Declaration. `DefineCapability` refuses it on an Operation whose name is a Reserved Word, since a Command Call can't start with one. As part of the declaration it is in the Host Manifest, the Group Fingerprint, saves and restore's declaration matching.
- **The Selector** is the Operation's name. Operation names are single words, so a Host Command takes comma-separated arguments and never Argument Labels.
- **Which Scripts get it:** a Script holding a Grant that includes the Operation. Two of a Script's Grants offering the same command name, including one Capability granted twice under two names, is a load error. With `GrantsAsUsed`, a Host Command call counts as a use of its Operation.
- **Clashes:** a Handler the Script defines with the same Selector shadows the Host Command, so a Host adding a command never breaks a Script that already handles that message. Tooling Lints the shadowing. An imported name that clashes with a Host Command is a load error, as an import clashing with a Handler is.
- **Modes** follow the Operation and the Command Call rules: a fire-and-forget Operation leaves `it` unchanged, an immediate one leaves its result in `it`, and a suspending one must be written `hide x and wait`. A mismatch either way is the load error `wrong mode`. A Host Command can't be called in a Guard.
- **Libraries:** a Host Command in a Library resolves when the Library is compiled, against its compilation declarations, after the Library's own Handlers and imports. It joins the Library's `needs`, so an importer without the Grant fails to load at its `use` line.
- **Folio** needs a Capability with `hide` and `show` Operations marked `command`, in place of its `folio` Library's Handlers, which set `the visible` of their argument. It is granted to every Play Session Script and to the Message Box. The hidden object above the Project, and the Message Box's `use hide, show from folio` line, are removed, and a Page or Project Script can no longer intercept `hide`.

[ADR 0114](0114-result-targets-apply-to-result-producing-calls.md) extends the result-producing forms with Result Targets. A fire-and-forget Host Command cannot have one (`wrong mode`); a Command Call resolved to the Message Path requires explicit `and wait` when it has a target (`missing and wait`). Resolution and suspension checks are unchanged.
