# TS Load targets 10× the Zig Core without a single-pass front end

[#1579](https://github.com/odogono/odgn-talk/issues/1579) set TS Load within 5× of the Zig Core and put a single-pass front end out of scope. [#1599](https://github.com/odogono/odgn-talk/issues/1599) reopened both questions. Profiling on `main` found no remaining hotspot. Load time is spread across the lexer, generator-driven parsing, checker context records and passes, semantic-tree allocation and lowering ([scope report](../research/ts-load-front-end-scope-1599.md), [results](../../bench/results/ts-load-1599/compact-frontend.md)).

A time-boxed prototype measured the cheapest structural slices of a single-pass front end. Compact Load trees, precedence climbing in one task and building the semantic tree in the checker's bounds walk keep Fuel, the Trace, code identities and diagnostics unchanged. With follow-up lexer and semantic-pass changes, large-Script Load takes about 45% less time under Bun and 53% less under Node than on `main` before #1599's changes. The two structural slices, precedence climbing and the merged walk, contributed about 15% between them, below the 25% bar set for continuing toward a fused recognizer, binder and lowerer. Further fusion would reorder site marking, whose results depend on order, and would still allocate the semantic tree that lowering reads. The remaining gap to 5×, about half of large-Script Load, is not plausibly reachable that way.

The TS Load target is therefore within **10×** of the Zig Core for `lifecycle/load-*` and `macro/*`, measured as #1579 does: Bun on an Apple M5 with alternating `--count 5` runs, plus a Node spot-check. A single-pass or incremental front end stays out of scope for Load. Incremental reanalysis for the LSP (#1584) is a separate workload and is not decided here. The Run target and the constraints from #1579 are unchanged: the code stays runtime-neutral and generates no JS.

On an idle machine after the follow-up lexer and semantic-pass changes, TS Load measured 5.8–6.6× of Zig for the small Script, 8.1–8.7× for the large Script and 6.7–7.2× for `macro/*`, all within the target.
