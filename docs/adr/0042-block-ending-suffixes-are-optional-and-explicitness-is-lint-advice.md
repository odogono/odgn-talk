# Block ending suffixes are optional and explicitness is lint advice

Every block accepts bare `end` as well as its explicit ending. Each ending closes exactly one innermost open block, and a supplied Name or keyword must match it; indentation and named endings never implicitly close intervening blocks. We chose optional suffixes over mandatory repetition or separate beginner syntax because short endings keep experienced Scripts concise while explicit endings remain useful for learning and reading nested blocks.

Explicitness is advice under [ADR 0027](0027-layers-are-a-tooling-view-over-one-language.md): `prefer-explicit-end` warns on each bare ending in `beginner` and is off in `standard`, without changing what loads or runs. Bare endings are a style choice, not Advanced Constructs. Beginner examples use explicit endings; the formatter preserves the user's tokens. The lint runs in the shared [tooling stack](../../tooling/stack/), through `northtalk lint`.

This narrows the mandatory ending spellings in ADRs 0019 and 0025 and the suspension-point spelling in ADR 0026. A Join still suspends only at its closing `end`, whether bare or written `end wait`; its `wait for all` head identifies the waiting block in the source. The optional suffix changes neither scheduling, lowering nor resource accounting. Unlike a special mandatory `end wait` exception, this keeps the ending rule uniform across all blocks. The language rules live in [chapter 2](../../spec/02-grammar.md#blocks), and the lint policy in [chapter 12](../../spec/12-sessions-and-tooling.md#layers-and-lints).
