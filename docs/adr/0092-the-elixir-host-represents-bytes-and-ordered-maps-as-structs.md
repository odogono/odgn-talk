# The Elixir Host represents Bytes and ordered Maps as structs

The Elixir Host converts every Value Encoding kind losslessly ([#993](https://github.com/odogono/odgn-talk/issues/993)). Two kinds have no faithful native Elixir form. An Elixir binary is both text and bytes, and an Elixir map has no order. So Bytes are `%NorthTalk.Bytes{data: binary}`, a binary is always text, and a map is `%NorthTalk.Map{entries: [{key, value}]}`, in order. A plain map with at most one key is accepted on input, since it has only one order; one with more is `invalid value`, never silently reordered. Every map a Script returns arrives as the struct.

The other tagged kinds get `NorthTalk.*` structs too: `Quantity`, `Range`, `Instant`, `CivilDate`, `Pattern`, `Object` and `Function`. Time has microsecond resolution ([ADR 0091](0091-time-has-microsecond-resolution.md)), which a `DateTime` holds exactly, but a `DateTime` also carries a zone and a display precision that the Value Encoding drops, so two `DateTime`s for one Instant can differ. So an Instant decodes to `%NorthTalk.Instant{unix_us: integer}`, which `NorthTalk.Instant.to_datetime/1` converts exactly, and a Civil Date, date-only or with a time, to `%NorthTalk.CivilDate{}`. `DateTime`, `Date` and `NaiveDateTime` are accepted on input. Keys and tags stay binaries, so Script input never creates atoms.

We considered tagging bytes as `{:bytes, binary}` and maps as keyword-like lists. A tuple doesn't say what it is in `inspect` and can't carry protocol implementations, and a list of pairs is indistinguishable from a list Value. We also considered treating invalid UTF-8 binaries as Bytes: whether a value is text would then depend on its contents.
