# The Message Layer accepts deep Values

Message Layer frames have no fixed JSON nesting-depth limit (#891). Values already nest without a Core cap, and the language-neutral embedding interface must carry those Values in either direction when memory and frame size permit. We remove the Go and Zig layers' 64-level admission guards rather than specify a transport-only depth restriction that prevents a Host from round-tripping a Script's result.

Removing a guard alone is insufficient. Zig's layer now feeds parsed JSON directly into the Core's iterative Value builder, including Function captures, instead of recursively re-encoding it. Go validates frame containers on a heap stack and reads raw Value Encoding spans into its finite envelope and declaration structures, bypassing `encoding/json`'s 10,000-level input ceiling. Its Value reader and writer use heap stacks too, with encoding error paths materialized only on failure. Reply assembly embeds the already-encoded Values rather than passing them through the standard JSON validator again.

The same stack discipline applies to the Go traversals that admission and Host crossings reach: Group ownership checks, display and Trace rendering, container logical size, and `any` Shape's Function scan. Otherwise a frame could decode successfully and still exhaust the WASI stack as a Request, a Host result, or error data. Size retains its container caches, and Function-error paths are materialized only on failure.

Native and WASI checks cover 100,000-level ignored fields, incoming arrays and maps and error data in replies, plus a 20,000-level round trip through a Run and an immediate Host Operation with Trace enabled. Script-produced results and interim needs are checked too. Malformed deep JSON still returns a protocol error without consuming a pending exchange. Physical memory and transport frame-size limits remain the backstops; no Script Limit Fault is invented for transport decoding. Source and declaration validity are still checked by their existing rules. A Host must choose a decoder that can read deep replies within its own resources.

We considered standardizing the existing 64-level incoming limit. It would protect the recursive readers cheaply, but would make a valid Value's admission depend on envelope and tag overhead and prevent deep Values in replies from being sent back. A symmetric limit would also discard Reports or interim needs after the underlying call had already run. Iterative decoding and Value traversal preserve the embedding interface without either restriction.
