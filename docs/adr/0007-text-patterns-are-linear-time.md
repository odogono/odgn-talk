
- Settled by #69: a match is a plain map `{text, range, captures, ranges}`. `text` is the matched text and `range` its Characters (1-based, inclusive, ADR 0011), and an empty match has an empty range at its position. `captures` maps each Capture name to its converted value and `ranges` to its range, with Nothing for a Capture that took no part, so a Capture named `text` can't clash. The Match Search gives a list of these maps. There is no `the match of`, and nothing implicit holds the last match after `matches` or `contains`: Captures come from `match … when <…>` or the Match Search. A `first match of <p> in s` could be added later without breaking Scripts.
