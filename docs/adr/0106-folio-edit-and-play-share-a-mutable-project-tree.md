# Folio Edit and Play share a mutable Project tree

Folio's editor and each Play Session own separate persistent `ProjectTree` instances. The tree is the sole writer of Project content and owns hierarchy, names, order and geometry indexes, plus copy-work indexes in Play, where Fuel is charged. Callers receive deeply readonly live views and use explicit mutation operations. This puts invariant maintenance behind one interface while preserving the separation between authored content and temporary Play State in [ADR 0041](0041-authored-projects-are-separate-from-temporary-play-state.md).

This supersedes ADR 0101's immutable document authority, reference-based change detection and snapshot history. The tree emits plain batched changes whose payloads are live, so a consumer that retains them, such as Edit's history, detaches its own copy; the editor adapts them to signals and targeted Page/asset rendering revisions. Forward/inverse changes provide atomic authoring updates and undo, including selection, entered scope and showing Page. Completed net-zero edits preserve redo and restore their starting content-state token. A separate monotonic change sequence detects intervening edits during asynchronous work. Saves and exports capture detached data before awaiting; stale Edit Message Box results are refused.

Keeping immutable document projections would preserve reference-based subscribers but maintain a second current representation. Binding temporary tree instances to Immer drafts would preserve snapshot history but rebuild indexes for each edit. We instead accept explicit notifications and change history throughout authoring so the same persistent mutation abstraction serves Edit and Play. Stable editor IDs survive history; live object identity is guaranteed during ordinary mutations, not restoration. Readonly views are a TypeScript contract, without runtime proxies or freezing live nodes.

The tree has no Core runtime or UI dependency. PlaySession supplies synchronous hooks to authorize before size-dependent copying and to install parent-first Core handles before tree publication. It retains Script, audio, navigation and provenance policy. There is no cross-Core rollback promise. Play then ran on the page thread under [ADR 0104](0104-folio-play-runs-on-the-page-thread-and-stop-is-cooperative.md); [ADR 0107](0107-folio-play-runs-in-a-supervised-worker.md) moves it, with its tree, into a supervised worker, and the Group Element policies of [ADR 0103](0103-folio-groups-are-nested-elements-with-page-wide-names.md) stand. ADR 0101's Preact/direct-DOM split and stable-ID policy also stand.
