# Mappings compose Shapes with restricted transformations

The design for [#579](https://github.com/odogono/odgn-talk/issues/579) keeps Shapes as acceptance descriptions and adds Mappings that combine selection, checks and transformation into a fresh map, inspired by [JSONPointer's ordered projection](https://github.com/odogono/elixir-jsonpointer). `transform` belongs to the existing `map` Library; its custom functions execute under an inherited runtime restriction that blocks effects and live state observations before they occur. This lets it collect independent failures without exposing partial output or allowing an unsuccessful rule to perform an effect.

Enforcement requires a documented stdlib-only intrinsic backed by a normative restricted-call instruction. An ordinary Library helper cannot provide it, and a Built-in that calls Script code would contradict the current Built-in execution contract. We chose runtime enforcement over static purity proof so unused effectful branches do not exclude otherwise valid computations, and chose enforcement over convention so the guarantee survives helper calls, catches and cleanup. The restriction permits inputs, captured locals, Constants and immutable object identity metadata; it does not make Mapping execution available in Guards.

This records an agreed design, not implemented support. The [design handoff](../research/script-shapes-and-mappings.md) specifies the boundary and diagnostics. Compiler access, machine execution, preemption/restore behavior and pricing must be specified and implemented before this guarantee can ship. Collecting ordinary callback errors deliberately qualifies the current Library convention of propagating those errors unchanged; Limit Faults still escape.
