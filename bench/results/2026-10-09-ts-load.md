# TS Load optimization, 2026-10-09

Evidence for [#505](https://github.com/odogono/odgn-talk/issues/505), comparing
baseline commit `2372361` with the issue's working-tree changes on this date.
The [raw measurements](2026-10-09-ts-load.json) include all six runner outputs.

On an Apple M5 (10 cores, 24 GiB), darwin arm64, with Bun 1.4.2, language
1.0-rc.2 and Cost Model 0, three alternating baseline/optimized pairs measured
`lifecycle/load-large` at 26.86–28.51 ms before and 15.08–15.47 ms after.
The median of the three Load medians fell from 27.74 to 15.17 ms: about 45%
less time, or 1.8× faster. `lifecycle/load-small` fell from 43.96–44.42 µs
to 29.83–33.54 µs; its median of medians fell from 44.29 to 30.04 µs.
Run timings remained similar between pairs. Each workload kept its expected
result and Fuel (1 / 7 for small, 1291 / 4609 for large).

Each run started a fresh Bun process, and a baseline run was immediately followed
by an optimized run, with no other test or benchmark jobs running. The command was:

```sh
bun bench/ts/src/measure-ts.ts lifecycle/load
```

The ordinary report command uses this same runner:

```sh
bun run bench --filter lifecycle/load --only ts --no-save
```

Timing is advisory. An earlier isolated baseline report measured 49.49 ms and
one final optimized report measured 14.66 ms, so the paired measurements above
are the comparison used here. Host bytes in these reports measure Run heap
growth, not Load allocations.

The CPU profile's checker line samples concentrated on per-element Map writes,
token-bound bookkeeping and semantic conversion. The change keeps traversal
context, bounds and converted elements in one local record per syntax element,
reuses those records in ordered passes, and avoids reversed array copies and
per-child `flatMap` arrays. It also avoids child filtering for productions that
do not classify names. Syntax nodes remain reusable with different check options.

Import discovery converts only `use` declarations. Decision checks collect facts
once, index only `veto`/`pass` positions, and convert only deciding Handler bodies.
The selection retains Declaration wrappers, including `private` declarations.
The remaining checker and lowering passes still check the entire retained source.

Validation: 5,607 Core/tooling tests passed, one optional Deno sqlite test was
skipped, and all 352 TS Corpus cases passed. Workspace typechecking, lint,
formatting of changed TS files and the workspace build passed. Existing diagnostic
and disassembly expectations were unchanged.
