# Session observation and declaration documentation

This is a normative extension of [chapter 12](12-sessions-and-tooling.md), settled in [#370](https://github.com/odogono/odgn-talk/issues/370). The command catalogue is [session.toml](data/session.toml); the embedding interface and [Run accounting](09-embedding.md#run-accounting) supply runtime observations. [ADR 0065](../docs/adr/0065-run-accounting-is-returned-to-every-host.md), [ADR 0066](../docs/adr/0066-fuel-measurements-follow-spawned-runs.md) and [ADR 0067](../docs/adr/0067-inspection-is-replayable-ordinary-execution.md) explain the choices. Current support is documented in the [TS](../impl/ts/README.md#the-session-host) and [Go](../impl/go/README.md#repl-and-session-transcripts) guides.

All command output uses chapter 11's display form, including map insertion order. Maps specified here are constructed in the field order listed, omitting only explicitly optional fields. Error rows use the existing Session error projection: remove Core-generated `message` and `at` fields; source locations, when part of ordinary failure output, remain in their existing separate position. Apply that projection to caught getter errors and `trace end` errors too. Never expose Host-only failure detail as normative output.

## Declaration documentation

A contiguous block of `--|` line comments immediately preceding a named top-level function, Handler Clause, Constant or Script Variable is its Declaration Documentation. Imports, local bindings and anonymous Lambdas have none. Leading indentation before the marker is ignored. Remove `--|` and at most one following ASCII space from each line, then join the remaining text with LF. Preserve all other spaces, empty marked lines and text; do not interpret Markdown or normalize the source text. A blank unmarked line, intervening ordinary comment or another declaration ends attachment. A trailing comment on another declaration is never a leading doc block.

- **Prompt:** a leading doc block keeps an Entry incomplete until its declaration is complete. On submission a block followed by a statement, expression or unsupported declaration is refused with `! bad arguments`, without changing Session Source. A blank line breaks attachment even at the prompt; a later declaration can still be submitted but has no documentation from that block. Cancelling unsubmitted input records no Entry and changes no source. Cancelling submitted execution keeps the ordinary cancellation behavior.
- **Source:** retain attached comments with their declaration through insertion, redefinition, export and reload. An undocumented replacement removes old documentation. Each Handler Clause has its own block, in declaration order; no clause inherits another's block. A repeated Script Variable declaration replaces its documentation along with its initializer.
- **Identity:** an Import alias resolves to the defining declaration's documentation. Runtime Function Values resolve by defining code identity and body, never merely by `functionName`. Retain defining-source versions while referenced by Session state, saved Sessions or Function Values. A stale Function Value shows the old documentation even if calling it would raise `function gone`. A Lambda has no attached documentation.
- **Built-ins:** use the catalogue's descriptive text in `stdlib.toml` as their documentation; Library exports use their source blocks. Missing documentation is empty text, not invented prose.
- **Tooling:** hover and apropos use the same attachment and resolution rules as describe. The formatter preserves every marked comment and never moves one across a declaration or removes the last blank line separating it. Styling in hover remains outside parity.

## Names and passive describe

`:describe <target>` accepts a current name or full Handler Selector. A Selector is the canonical Selector spelling, not a Handler head with argument variable names. It also accepts a map in the display form with exactly these keys:

| Target | Keys |
| --- | --- |
| Current binding | `{name: <text>, origin: "session"}` |
| Built-in, even when shadowed | `{name: <text>, origin: "builtin"}` |
| Library export, imported or not | `{library: <text>, name: <text>, origin: "library"}` |

The map forms are the canonical targets printed by apropos. A current Import binding uses its current alias and `origin: "session"`; its defining origin is shown separately. Library-qualified targets use the exported name. Public Library exports only are discoverable; private declarations stay hidden. An unresolved plain name is refused with `! no such name`; malformed/extra target fields give `! bad arguments`. No name lookup executes an initializer or reads a Host Object property. Existing binding precedence decides shadowing.

For each match print `describe <map>`, then its documentation and any passive value rows. The header map has `target` (the canonical target map), `origin` (`"session"`, `"builtin"` or the defining Library name), `declaration` (`"function"`, `"handler"`, `"constant"`, `"variable"` or `"builtin"`), `signature` and, for a Handler, `clause` (one-based within that Selector). `signature` is the declaration's source header through the end of its grammar head, excluding leading/trailing whitespace and comments; internal source whitespace is retained. Built-ins use their catalogue signature. Print `doc <text>` once for each match, including empty text, with the complete documentation encoded as one display-form text value. Handler Clauses print separately in declaration order. This does not select a clause by executing its Guard.

Runtime binding values, where available, are rendered by the passive value rules below. A function declaration adds `arity <range>` (required through total parameters); a Handler's signature supplies its labelled parameters. Unimported Library declarations are described from source, without evaluating a Constant or manufacturing a Function Value.

## Value inspection

`:inspect <expression>` accepts exactly one expression, including a multiline one. Parse and check it before executing; statements, declarations and trailing input are refused with `! bad arguments`. Diagnostics use the expression's own source positions. The expression is evaluated once as an ordinary implicit Entry, with normal suspension, console I/O, cancellation and errors. Replace its ordinary success-value echo with these rows, in this order:

1. `value <map>` with `kind` (the `kindOf` name) and `value` (the actual value in the display form).
2. `size <n>` for a list, map, bytes or text: respectively element, key, byte or grapheme count.
3. `field <key-as-text> = <value>` for each map key in Unicode code-point order; this is one level, not recursive inspection.
4. For a Function Value, `function <map>` with `name` (`functionName`, possibly Nothing), `arity` (`functionArity`) and `home` (Home Script name), followed by `doc <text>` from its defining source, or empty text for a Lambda.
5. For a Host Object, `object <map>` with `kind` (Object Kind), `id` and `disposed`, then `property <map>` per declared property in Unicode code-point name order. A property map has `name`, `shape`, `readOnly`, `getCost` and `setCost`, using the authoritative Object Kind declaration data model. Shape and cost declarations use the plain-map declaration representation from chapter 9. An omitted Shape is `"any"`; each omitted cost is `{fuel: 0, alloc: 0}`, and an omitted allocation component is `0`. `setCost` is Nothing for a read-only property. Print cost map keys in `fuel`, `alloc` order.

Passive describe uses these same rows for a binding value, but never the getter-reading stage. It does not call `Inspect()` merely to obtain metadata: the Session Host retains declaration metadata and uses an explicit snapshot only when it needs a current Script Variable value. Such a snapshot is the ordinary `vars` Host Input and appears in the Trace. It must be performed once for a describe of a current variable, even if cached state would suffice. Other name kinds cause no snapshot. Rendering held values and metadata charges no Script Fuel.

### Reading Host Object properties

After successful expression evaluation of a Host Object, retain that exact returned Value and enumerate its actual Object Kind's readable declared properties, not a possibly stale Host Manifest. Do not traverse nested values or call functions found in fields. The Core-held `id` is already in the object row and is not an additional getter read.

The Host extends the Session Script with a generated Handler and requests it with the object and sorted property-name list as arguments. The expression uses the existing implicit Entry naming sequence. For the reader, take the first later integer `n` for which `entry<n>` and all identifiers obtained from the [normative reader template](session/inspect-reader.talk) are free of authored/current imported binding and Selector-first-word conflicts. Replace every identifier token beginning `entry0` in that template with the same suffix after `entry<n>`; change no other bytes. The template is UTF-8 with LF endings, including its final LF. Request Selector `entry<n>:to:` with the retained object and sorted name list; advance the implicit Entry counter to `n`. Both generated declarations are excluded from Session Source and export. This fixes lowering, instruction/output costs and Trace source identically on both Cores, without relying on independently written equivalent helper programs.

- This is a second Delivery and a second Run, not a descendant of the expression Run. Both appear normally in accounting. There is no invented causal edge between Host requests.
- The expression and reader each get the current `:limits` override when requested. There is a Pump boundary between them, where other work can execute or dispose the object. The two Runs are not one atomic inspection.
- On expression completion, request the reader immediately, before returning control to accept a new Entry. It is the Foreground Run while executing. An asynchronous expression completion follows the same rule; cancelling an unfinished expression never starts a reader.
- Each successful getter prints `read {name: <name-as-text>, value: <value>}`. Each ordinary Script error prints `read {name: <name-as-text>, error: <error-map>}` and continues. Use ordinary error handling, including its costs and effects; no rollback or retry is added by inspection.
- A Limit Fault, cancellation or fatal effect failure ends the reading Run using the ordinary Session failure output. Already printed rows remain. The reader's successful result is Nothing and has no extra success-value echo.
- Console output for reader rows uses the ordinary `console.write` path and therefore ordinary instruction/output costs. Author-generated console output during either Run remains in normal execution order. The Session Host does not reinterpret arbitrary console strings as protocol messages.

An expression returning any other kind needs no reader Run. There is no new language Built-in, opcode, reflection syntax or free execution allowance.

## Name discovery

`:apropos` lists every discoverable name; `:apropos <query>` matches a literal substring of its name. A query may be raw trimmed text or a single display-form text value; the quoted form permits leading/trailing spaces. Use the language's pinned Unicode full default lowercase mapping followed by NFC (the Built-in `lower` rule) on both strings, without locale rules, regex or matching documentation prose. Do not use the platform's locale-sensitive case conversion.

Include current bindings, Built-ins (even shadowed) and public exports of every registered Library, whether imported or not. Keep current aliases and defining exports as separate targets. Group a Handler's clauses under its full Selector. Sort by original name in Unicode code-point order, then origin (`session`, `builtin`, `library` in that order), then Library name. No match prints no rows.

Print `name <map>` for each target: `target`, `origin`, `available` (whether this exact target is usable without a new Import or a shadowing change), and `import` (Nothing, or the exact source of a `use` declaration for that exported name). Follow with `doc <text>` for a non-Handler or `doc <clause-number> <text>` for each Handler Clause. Search output does not silently import anything. Exact declaration signatures and passive values are obtained by passing the printed target to describe.

## Dispatched Run tracing

`:trace` prints each active filter as `trace <Selector-as-text>`, sorted by Selector in Unicode code-point order. `:trace <selector>` adds the trimmed full Selector; `:untrace <selector>` removes it and bare `:untrace` removes all. Accept Selectors without a currently declared Handler so future messages can be traced. A syntactically invalid Selector is `! bad arguments`. Mutations print no acknowledgement and are idempotent. Each command is recorded.

At dispatch, match the actual message Selector across the Group and latch whether the Run is traced. Print `trace start <map>` with `script`, `run`, `selector` and `args`. A terminal event prints `trace end <map>` with `script`, `run`, `selector`, `outcome` and the outcome-specific `result`, `error`, `limit` or `effect` fields of the public RunEnd report. A discarded Run instead has `outcome: "discarded"` and `reason`. Do not include non-parity Host-only error detail.

- Output is flushed at the enclosing Host call's return, in lifecycle event order, after ordinary output produced during that call and before Fuel milestone output. Start and end can both appear in one batch. This is a dispatch view, not a claim of immediate mailbox arrival notification.
- A removed filter does not suppress an already-latched terminal event. An added filter does not retroactively trace an existing Run.
- Local/imported calls sharing a Run are not traced separately. Foreign Function Value Runs are accounting events, but have no message Selector and do not match trace filters. Helper inspection Runs are ordinary dispatched Runs and can match an explicitly named helper Selector.
- Messages dropped before a Run exists have no dispatch/terminal pair. Suspensions and resumptions add no trace output.

## Fuel measurements

`:fuel <entry>` accepts one statement or expression with ordinary multiline completeness, diagnostics and execution. Refuse declarations or Session Commands with `! bad arguments` before applying source changes. Each successfully submitted executable Entry is numbered normally; its implicit `entry<n>` name identifies the Fuel Measurement. Refused syntax/checking creates no measurement.

The measured family is the Entry's root Delivery and every Run and queued message transitively spawned from it. Include sends, waited sends, Joins, foreign Function Value calls, Message Path forwarding and implicit error Handlers. Local calls already spend their caller's Fuel. Include detached descendants even after the Entry returns. Capability answers and deadlines resume existing members rather than creating new roots. Exclude later Host timer/Notification Deliveries, independent Host requests, and pre-existing waiting Runs that a message wakes.

Keep each member's latest cumulative Fuel, including charges outside its execution stretches, and count ended/discarded Runs exactly once. The total is exact at the completed Host boundary, including active members; never estimate it from Segment sums. A measurement remains pending while any member is live or any descendant message is queued, including an admitted message that never gets a Run. A declaration/reload cannot erase spent work.

Print `fuel <map>` with `entry`, `fuel`, `state`, `interrupted`, `runs` (live members) and `queued` (pending descendant messages). `state` is `pending` while work remains, otherwise `interrupted` if any member or descendant message was discarded by lifecycle replacement/Stop, otherwise `complete`. Errors, Limit Faults and explicit cancellation are terminal work, not lifecycle discard. Fuel is reported in the ordinary decimal integer display form, not elapsed time.

- Print once after the initiating Host call yields or completes. If it settles there, print only the final row. Otherwise print again on settlement, even if the total is unchanged. Bare `:fuel` prints all measurements in Entry-number order with exact current totals and does not itself Pump or inspect the Group.
- Background Pumps do not print intermediate Fuel rows automatically. A pending measurement may remain pending indefinitely. Concurrent measurements have distinct root Deliveries; shared external consequences do not get charged to both.
- If a lifecycle call discards some members, latch `interrupted` immediately, retain their final Fuel and continue tracking surviving members. Emit the final row only when no tracked work remains.
- A root Delivery dropped or cancelled before dispatch has zero Fuel; its queue accounting still closes the measurement. Only lifecycle discard sets `interrupted`.

## Save and restore

A Session save includes trace filters, latched tracing for live Runs, measurement IDs/membership/totals/interruption flags, the implicit Entry counter, source-version documentation and the Core's queued ancestry. Object resolver state records which captured identities still resolve; external native object state is not rewound by a Group save.

On successful `:restore`, abandon current observation state and replace it with the saved copy. After the ordinary restore/discard output, print `fuel abandoned <entry-as-text>` for every currently pending measurement in Entry order, even if a measurement with that name exists in the save. Do not add their future Fuel to the restored totals. Restored measurements continue from saved totals and restored tracing latches retain their eventual terminal row. Refused restore changes none of this state. Captured dynamic objects use the recorded resolver outcomes; no Host Object is silently recreated as live merely because its id was once seen.

## Object crossings in Session Transcripts

The `% ` prefix introduces one JSON object on one physical line. The envelope grammar is normative here and the framing is in `trace.ebnf`. Output beginning with `%` is escaped with the existing leading apostrophe. Each envelope has exactly the fields below; reject unknown fields, duplicate JSON keys, invalid identities, out-of-order crossings or leftover inputs as a malformed Transcript. This is replay data, never executable host code.

JSON is compact UTF-8 with envelope/declaration object keys in Unicode code-point order, no insignificant whitespace and the Value Encoding's string/number escaping rules. Embedded Script Values preserve the Value Encoding's map insertion order and are never recursively key-sorted. Integer metadata is a JSON integer below 2⁵³ and canonical unsigned decimal text in a JSON string at or above 2⁵³; counters have no format-imposed maximum. Source remains exact text. Object references in envelopes are `{kind, id}`. At a Value position, a Function Value uses the Transcript-only tag `{"$sessionFunction": <handle>}`, including when nested inside a list or map. A `function` record binds that handle to an exact previously exposed Function Value, not to its display name or display text. This is a replay reference, not durable Value Encoding; an unresolved or invalidated handle is malformed. Ordinary maps with dollar-prefixed keys continue to use `$map`, so they cannot collide with the tag.

| `type` | Other fields | Meaning |
| --- | --- | --- |
| `kind` | `name`, `props`, `parentKinds` | Register the Object Kind; properties use the worker `define-object-kind` declaration model, sorted by name. |
| `object` | `object` | Register an identity before its first use; no native pointer is recorded. |
| `setup` | `objects` | Initial well-known bindings, a map from Script binding name to object reference, before session Load. |
| `property-begin` | `crossing`, `object`, `property`, `operation`, optional `value` | Start an actual Host getter/setter callback. `operation` is `get` or `set`; `value` is present only for a set. |
| `property-end` | `crossing`, `reply` | Finish that callback with exactly one worker `prop-result` alternative (`value`, `ok`, `fail` or `hostError`). |
| `input` | `request`, `reply` | A Host action made outside ordinary Session Command translation, with worker-protocol fields and its synchronous reply. |
| `function` | `handle`, `exposure`, `path` | Bind a portable handle to a Function Value in a Core-to-Host value exposure, as below. |
| `resolve` | `objects` | Ordered `[{object, resolved}]` outcomes for a Restore resolver request. |

A **Value Exposure** is an Operation callback's argument list, a property setter's argument, any public report whether or not it carries a Value, or a returned Script Snapshot's variable values. Number these exposures in observation order from 1, including those without Values or functions. Use the report/callback's actual Value tree, before JSON encoding; a list indexes from zero and a map follows its stored keys. The `path` array traverses that tree using numeric list indices and text map/record field names; report paths start at the report itself, callback paths at the argument list (a setter uses a one-element list), and snapshot paths at the Script-name-to-variable-map view. Emit a `function` record for every Function Value leaf, immediately when exposed, in depth-first field/element order. Assign handles `f1`, `f2`, ... in that order; do not deduplicate by display or name. Replay checks the exposure/path identifies a Function Value and binds its actual value to the recorded handle. Host adapters retain which exposed handle supplied a returned function; they cannot synthesize a function or silently resolve a stale handle to newer same-name code.

Function-handle and exposure counters, like crossing counters, belong to the recording and do not rewind. A successful Restore invalidates handles from the old Group; functions exposed by restored Runs or snapshots get new handles. A refused Restore invalidates none. This preserves defining-code identity without pretending that external function handles survive Group replacement. Function documentation retained in saved Session state is independent of this transport handle table.

`crossing` is a monotonically increasing positive integer for the recording, not a Core call id. It is not rewound by restore. Property actions queued before a failing callback returns are recorded and replayed before its failing `property-end`, just as for a successful callback. At most one property callback is active: reentrant worker execution remains forbidden. Kind records normalize omitted Shapes to `"any"`, omitted costs/allocation components to zero, absent parent kinds to `[]`, and set `readOnly` from setter absence; omit `setCost` in a read-only kind declaration (the passive display row uses Nothing). `kind` and `object` records may appear inside a callback before a returned value or queued action first uses them. A duplicate identical registration is redundant and must not be emitted; conflicting registration is malformed. Parent changes and disposal use ordered `input` records, not mutable fields on identity records.

`input.request` is a normalized worker request: `kind` contains the worker operation name and the other fields are that operation's payload, omitting transport `m`, `ref` and Group handles because the envelope addresses this Session Group. Replay reconstructs those transport fields when using a worker. The allowed operations are `set-parent`, `dispose`, `deliver`, `request`, `cancel-delivery`, `broadcast`, `call`, `decide`, `answer`, `fail`, `settle`, `stop`, `cancel-run` and `revoke`; each has exactly chapter 9's worker fields. `reply` is `{ok: <worker-success-payload>}` or `{error: <Host-error-code>}`: normalize transport `{ref, ok}` to the former and `{ref, err}` to the latter, retaining the Host error code and omitting non-parity detail. The success payload is `{}` for an operation with no result. Replay performs the action at the recorded position and compares its synchronous reply. Calls prohibited during a callback remain prohibited; a refused call is reproduced as a refusal, not applied. Worker operations that execute code, replace definitions or Pump are never smuggled through this envelope.

The live Session environment must record registrations and actions made by its Host adapters, including actions queued by property callbacks. Before starting it supplies initial object bindings (empty by default), using the Core's real Object Kinds. The Session Script remains unowned and `me` remains Nothing. Dynamically encountered objects are registered before use; registration carries no extra Script-visible read or Fuel charge.

Replay preloads initial registrations/setup, creates dummy native identities, then executes normal Entries and Commands. At an actual property callback it consumes a matching begin record, performs intervening recorded actions/registrations in order, and returns the matching end reply. It never invokes the original external getter. Values, Shape checks, conversion costs, failures and queued action timing still pass through normal Core machinery. A property failure before a callback (for example `object gone`) needs no fabricated begin/end record. Between Host calls, recorded external `input` records execute in their recorded positions; `@` still supplies each real Clock reading. On restore, dummy objects resolve exactly as recorded.

A standalone Transcript contains all this setup; it must not depend on `case.toml`, a Host Manifest or the original native objects. Corpus Trace replay derives object declarations and action scripts from these envelopes and checks the same canonical Trace; new public accounting records are not Trace records. Existing Transcripts without `%` records retain their empty object setup and unchanged meaning.
