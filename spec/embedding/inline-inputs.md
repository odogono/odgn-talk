# Inline Trace observation and Host Input admission

The optional `inline-inputs-v1` Message Layer feature lets an embedding adapter
preserve native Go's synchronous Trace sink and concurrent input queue contracts
([#1051](https://github.com/odogono/odgn-talk/issues/1051)). It extends
[paused-crossing admission](paused-crossing-inputs.md) without changing protocol
version 1, the Trace catalogue, Fuel, Clock readings or ordinary need/result
exchanges. Hosts using other features retain their existing reply timing.

## Observation and ordering

A synchronous sink observes a complete record before its producer writes the
next record. Inputs it generates are admitted before that producer continues.
Admission retains the ordinary rules: accepted Deliveries, settlements, Revoke
and other ordinary inputs wait for the next Pump's input batch. Stop, CancelRun,
RewindRun and refused-input records join the active Pump's control queue; they
land at the next Host crossing or Stretch boundary. A control generated by the
terminal `pumped` record belongs to the following Pump. Outside a Pump, queued
inputs wait for the next Pump. The sink cannot execute another worker or wait
for a future requiring that worker to finish.

Inputs from other goroutines share one FIFO admission queue with sink-generated
inputs. An input arriving during an export keeps its place until the running
export services it at an admission checkpoint or its boundary. The admission
reply performs the ordinary validation and assigns the Core's ids and mailbox
reservations; merely storing a frame is not success. `OnReady` remains Host work,
called after successful admission and outside admission/registry locks. The
current Pump never expands its captured ordinary input batch.

## Negotiation and inline frames

A transport advertises `inline-inputs-v1` only when it can exchange inline frames
while its worker stack remains active. A Host requests it in `hello.features` and
checks the reply before using it. The WASI reactor implements these inline
frames over stdin/stdout, each with a four-byte big-endian byte length and a JSON
body. Its normal `talk_buffer`/`talk_send` request and reply remain unchanged.
With [`chunked-wasi-v1`](chunked-wasi.md), a logical event or response may span
several bounded chunks; observation and acknowledgement wait for its final chunk.
No stdio exchange occurs without opt-in. A native Session may supply the same
inline transport explicitly; the ordinary sidecar does not advertise it.

During `talk_send`, the guest sends one of these events:

- `{"trace":["complete record"]}` observes exactly one record. The producing
  stack waits until the sink has returned and its admission replies have been
  observed. Refusals generated by a sink follow native queue/hold rules. Records
  already streamed never appear again in the final reply. Diagnostics remain
  available to build the typed Load error even after their records were streamed.
- `{"poll":true}` offers an admission checkpoint without a Trace sink. It does
  not run another Script, advance the Clock or add a Trace record or charge.
- `{"need":{"m":"release",…}}` invokes a Grant release hook synchronously,
  before the producer continues to its following record. Its fields are the
  ordinary `release` need's fields. It has no result payload.
- `{"reply":{…}}` carries an ordinary admission `ok` or `err` envelope, including
  its own `ref` and any available Trace. The enclosing worker stays active.

Trace, poll and release events may carry outer `abandoned` and `settled` lists
under the existing negotiated features. Process these even on polls without
Trace, before any following Host callback. Stop marks suspended and pending Join
Calls abandoned before invoking the first release hook.

The Host answers an event with either JSON `null`, acknowledging the event, or
an ordinary admission frame. Admission uses the paused-crossing allowlist, the
same Group and a ref distinct from the enclosing worker's. The guest processes
that frame on its current stack and sends its `reply` event; the Host can submit
more inputs before acknowledging with `null`. Worker reentry is refused with
its ordinary records. An adapter refusing a concurrent worker can include
`refuseWorker: true` on that worker frame: it remains a recorded reentrant
refusal even if serviced after the original export reaches its boundary. Only admission runs in this loop: it cannot execute guest
instructions or resume a waiting Run. Ordinary `op`, `prop` and `effect` needs
still return through `talk_send` and use their matching result frames.

The adapter serializes exports and drains its Go-side queue through these
checkpoints and export boundaries. It never calls a guest export from a sink or
while another export is running. Checkpoint frequency is an implementation
detail; an atomic instruction or compilation step may delay an admission reply
until its next checkpoint or export boundary. This adds no wall-clock latency
or performance guarantee. Malformed framing or failed inline I/O fails the
transport; it cannot silently acknowledge an input or drop a record.

## Acceptance

The Go adapter's public Host matrix queues Stop, Request, Revoke and refusals
from every record kind its fixtures produce, and compares exact Trace, Fuel,
typed Reports, future outcomes and inspected state with a separately compiled
native-Go Host. It covers execution, properties, errors, suspension, cancellation,
Decisions, diagnostics and inspection. Native Go's refused-input panic from the
terminal record is separately tracked in
[#1072](https://github.com/odogono/odgn-talk/issues/1072).

A Trace-disabled long export admits inputs from concurrent goroutines before
returning, including Delivery, Stop, CancelRun and Answer, preserves OnReady and
executes ordinary inputs at the next drain. Pure-Go/race/vet acceptance and
separate Linux amd64/arm64 and macOS arm64 cross-builds remain required. These
checks do not approve full API compatibility, performance limits or Go Core
retirement.
